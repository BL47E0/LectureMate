Good morning everyone. Today we are going to talk about process scheduling in operating systems. Let us start with a simple question. Why do we need scheduling at all? The answer is that a computer usually has only one CPU core available at a time, but many programs want to run together. The operating system must decide which process gets the CPU and for how long. This decision is made by a part of the operating system called the scheduler.

First, let us define a process. A process is a program in execution. Every process has a state. The main states are new, ready, running, waiting and terminated. A process in the ready state is waiting for the CPU. A process in the running state is currently using the CPU. A process in the waiting state is waiting for an input or output operation to finish, such as reading a file from the disk.

The scheduler uses a data structure called the ready queue. The ready queue holds all the processes that are ready to run. When the CPU becomes free, the scheduler picks one process from the ready queue. The act of switching the CPU from one process to another is called a context switch. During a context switch the operating system saves the state of the old process and loads the state of the new one. A context switch is pure overhead, because the CPU does no useful work for the user during that time.

There are two types of scheduling. In non-preemptive scheduling, once a process gets the CPU, it keeps it until it finishes or until it waits for input or output. In preemptive scheduling, the operating system can take the CPU away from a running process, for example when a higher priority process arrives or when a time limit expires.

Now let us look at the common scheduling algorithms. The first one is First Come First Served, usually written as FCFS. The process that arrives first is served first. It is simple, like a queue at a ticket counter. The problem is the convoy effect. If one long process arrives first, all the short processes behind it must wait for a long time. For example, if a process needs one hundred milliseconds and two other processes need only five milliseconds each, the short ones wait more than one hundred milliseconds.

The second algorithm is Shortest Job First, or SJF. The scheduler picks the process with the smallest CPU burst time. SJF gives the minimum average waiting time, which makes it optimal in that sense. However, there is a practical problem, because the operating system cannot know the exact burst time in advance. It can only estimate it using previous behaviour. Another problem is starvation. A long process may wait forever if short processes keep arriving.

The third algorithm is Round Robin. Round Robin is designed for time sharing systems. Each process gets a small amount of CPU time called the time quantum, usually ten to one hundred milliseconds. When the quantum expires, the process is preempted and placed at the end of the ready queue. If the time quantum is too large, Round Robin behaves like FCFS. If the time quantum is too small, there are too many context switches and the overhead becomes high. So choosing a good time quantum is important.

The fourth algorithm is Priority Scheduling. Each process is given a priority number and the CPU is given to the process with the highest priority. Priority scheduling also suffers from starvation, where low priority processes never get to run. The solution is called aging. In aging, the priority of a waiting process is slowly increased as time passes, so eventually it will run.

Let us also talk about the criteria used to compare algorithms. CPU utilization is how busy we keep the CPU. Throughput is the number of processes completed per unit time. Turnaround time is the total time from submission of a process until it completes. Waiting time is the total time a process spends in the ready queue. Response time is the time from submission until the first response is produced. A good scheduler tries to maximize CPU utilization and throughput, and to minimize turnaround time, waiting time and response time.

To summarize, scheduling decides which ready process gets the CPU. We studied FCFS, SJF, Round Robin and Priority scheduling, along with the problems of convoy effect and starvation.
